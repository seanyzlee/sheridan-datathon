# Sheridan Datathon 2026 — Tangerine "Resilience Rewired" (product name: Toonie)

The build plan is in `docs/ROADMAP.md`. Read it at the start of every session and work on the first unchecked task.
Current phase: **Phase 4 wrap-up, then Phases 5–6** (Phases 0–3c done).

The production app is `api.py` (FastAPI) + `web/` (React, TypeScript, Vite, Recharts). Build with `npm --prefix web run build`, run with `.venv/Scripts/python.exe -m uvicorn api:app --port 8000`. The API only shapes engine/plan/simulate/discovery output; never compute numbers in the front end. Charts follow the `dataviz` skill (no dual axes, a table view per chart, colours from `web/src/theme.tsx`: blue = today, tangerine = after the shock). Restart uvicorn after editing a Python module. The web app has a simple view (advisor with a customer, plain words) and an advanced view (analysts and judges); gate extra detail with `useAdvanced()` from `web/src/state.tsx`, never by removing it. The Streamlit app (`streamlit run app.py`) is kept as a rehearsal fallback. Gemini (`gemini_client.py`, key `GEMINI_API_KEY` in `.env`) is for language only: reading twist cards and rewording the advisor note. Never let it produce a number; keep the number guard and the silent fallback to `twist.py` / `plan.summary`. The assistant (`assistant.py`) answers only through tools: add a read tool that returns pre-formatted engine figures, or an action tool that returns an `action` for the browser (applied in `web/src/components/Assistant.tsx` with Undo); never let it write data. The 3D stress surface (`web/src/charts/StressSurface.tsx`) uses React Three Fiber 8 / drei 9 because the app is on React 18 (fiber 9 needs React 19); keep it lazy-loaded, keep `frameloop="demand"` (the decorative `Decor3D` scene animates only while on screen), keep decoration to empty states, and keep the `RobustResizeObserver` polyfill on the Canvas (some embedded browsers never fire ResizeObserver). Shock Autopilot (`autopilot.py`, `web/src/components/Autopilot.tsx`) is the headline customer feature: every ladder figure comes from engine.runway; keep it that way. Motion goes through `web/src/motion.ts` (GSAP + useGSAP, reduced-motion aware). The ship bar is `docs/QUALITY_GATES.md`; run `tools/audit.py` (app on :8000) before calling UI work done. Write files with `encoding="utf-8"` from Python: the Windows default (cp1252) corrupts characters like ×.

Restart `streamlit run app.py` after editing an imported module (`ui.py`, `engine.py`, ...): the server keeps the old module; only page scripts reload.

Rebuild the C++ core after editing `hpc/`: `uv pip install --python .venv/Scripts/python.exe ./hpc` (bump the version in `hpc/pyproject.toml` so uv reinstalls).

Use the project venv: `.venv/Scripts/python.exe` (Python 3.12). The system Python 3.14 has numpy blocked by Windows Application Control. Run tests with `.venv/Scripts/python.exe -m pytest`.

Engine numbers must match the judges' definitions (I, S, F, H, B, P and the runway formula) in the roadmap's Data Model section.

The C++ HPC core (`hpc/`, pybind11 + OpenMP) adds Monte Carlo survival probabilities and bank-wide stress tests. It never replaces the judges' formula, must match it when noise is off, and always has a NumPy fallback (`sim_numpy.py`) with the same function signature.

Snowflake is scrapped; do not add it back. The final product uses Tiger Data (TimescaleDB hypertables and continuous aggregates for the live feed). Its profile numbers must match `engine.profile()`. Credentials live only in `.env`, which is git-ignored. Every panel the live twist needs must also work offline from the Parquet cache.
